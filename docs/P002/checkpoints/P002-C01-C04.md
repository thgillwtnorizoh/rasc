## Objective / Supported profile / Functional changes & integration
1. **Animation FPS user setting:** Display-synced by default (uses every WPF `CompositionTarget.Rendering` opportunity); presets 30/60/90/120/144/165/240; editable ComboBox accepts any whole integer **15..240** including 75/123. The `ClassicAnimationFrameGate` advances an absolute target-time phase accumulator, not a naive last-rendered delta: this prevents a 120 target on 123.3 callback/sec stream from accidentally halving to ~61 visual updates/sec. FPS is **average requested visual updates**, not physical monitor frames, and never changes the monotonic 450ms entrance/exit or six-second hold timeline. Callback diagnostics now distinguish WPF rendering callbacks vs actually **applied animation visual updates**. No request to change source/Steam events or game FPS.
2. **DPI / resolution-aware popup size:** `ClassicPopupScale.Resolve` uses primary-screen **logical** height, default 1080-DIP baseline, Auto clamp 1..2× with fit-to-work-area, or manual percentages **100/125/150/175/200/250**; user can change while popup visible. WPF already accounts for OS DPI, so Auto avoids blindly multiplying OS scale a second time. 2560×1440/100% => 1.333× WPF scale (~320×125 physical px per card); 1440p at125% OS DPI => logical screen1152 and ~1.067× UI scale, ~320px physical card width. A 4K/100% screen =>2×.
3. **Accepted art preserved:** `ClassicToastCard.xaml` **UNCHANGED** from C02 visual baseline; original dark gradient, Helvetica Regular approximate font, text/icon placement and all animation/occlusion semantics preserved. The shared stack surface uses `Viewport.LayoutTransform = new ScaleTransform(factor,factor)` while outer window width/height and bottom/right anchoring scale correspondingly. Physical pixel-grid clipping uses combined WindowsDPI × popupScale; source-dimension cards remain logically 240×94 with 3-card viewport240×282.
4. **Per-monitor-aware platform:** `app.manifest` opts into Windows PerMonitorV2 (Windows10+ where supported), `ClassicToastStackWindow` repositions on Windows DPI, display or work-area configuration changes and notifies presentation host to reclip active cards. Still scoped to **primary desktop work area**; moving an independently injected Steam overlay between monitors/exclusive fullscreen not supported.
5. **Persistence and safety:** `ClassicPresentationSettingsStore` persists `AnimationFps` & `PopupSizePercent` as small JSON at `%LOCALAPPDATA%\RASC\appearance.json`. Invalid/corrupt/oversized values default safely. Writes temp+move, catching unauthorized/file IO errors. Preview and preferences never mutate GC `achievements.txt`, `history.db`, unlock events or Steam.
